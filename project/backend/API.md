# FindIT API (v1)

Base URL (local Docker): `http://localhost:8001/api/v1`

Interactive docs are also generated by Scramble (see `config/scramble.php`).

## Conventions

- Send `Accept: application/json` on every request, otherwise errors may come back as HTML redirects.
- JSON bodies use `Content-Type: application/json`. Endpoints that take files use `multipart/form-data`.
- **Auth:** Laravel Sanctum bearer tokens. Get one from `POST /login`, then send `Authorization: Bearer <access_token>`.
- Resource responses are wrapped in `{ "data": ... }`, except `POST /login`, which returns a plain object.
- Validation errors are `422` with the Laravel shape:
  ```json
  { "message": "The title field is required.", "errors": { "title": ["The title field is required."] } }
  ```
- Common errors: `401` missing/invalid token, `403` not allowed, `404` not found, `422` validation, `429` rate limited (check `Retry-After`).

## Endpoints

| Method | Path | Auth | Verified e-mail | Rate limit |
|---|---|---|---|---|
| POST | `/register` | – | – | 5/min |
| POST | `/login` | – | – | 5/min |
| POST | `/logout` | token | – | – |
| GET | `/user` | token | – | – |
| GET | `/email/verify/{id}/{hash}` | signed URL | – | 6/min |
| POST | `/email/resend` | token | – | see below |
| GET | `/posts` | – | – | – |

| POST | `/post/{post}` | token (author) | – | – |
| DELETE | `/post/{post}` | token (author/admin) | – | – |

## Auth

### POST `/register`

Creates an account and sends a verification e-mail. Does **not** log the user in.

| Field | Rules |
|---|---|
| `username` | required, 3–30 chars, `[a-zA-Z0-9_-]`, unique |
| `email` | required, valid e-mail, max 255, unique (stored lowercase) |
| `password` | required, min 8 chars |
| `password_confirmation` | must match `password` |
| `terms_accepted` | required, must be accepted (`true`/`1`) |
| `privacy_policy_version` | required, string |

**201**
```json
{ "data": { "id": 1, "username": "jane", "email": "jane@example.com", "email_verified_at": null } }
```

### POST `/login`

| Field | Rules |
|---|---|
| `email` | required, valid e-mail (case-insensitive) |
| `password` | required |
| `device_name` | optional, max 255 (token name, default `auth_token`) |

**200**
```json
{
  "access_token": "1|abc...",
  "token_type": "Bearer",
  "user": { "id": 1, "username": "jane", "email": "jane@example.com", "email_verified_at": null }
}
```
- `422` on wrong e-mail/password (error on `email`).
- `403` if the account is banned (only revealed after a correct password).
- Unverified accounts can log in; they just can't create posts.

### POST `/logout`

Revokes the current token. **200** `{ "message": "Successfully logged out." }`

### GET `/user`

The signed-in user. **200** `{ "data": { "id", "username", "email", "email_verified_at" } }`.
`401` if the token was revoked, so clients can use it to validate a stored token.

### GET `/email/verify/{id}/{hash}`

The link in the verification e-mail (signed URL, don't build it by hand).

- **200** `{ "message": "Email address verified." }`
- `403` invalid hash or signature, `410` already verified.

### POST `/email/resend`

Sends a new verification e-mail to the signed-in user.

- **202** `{ "message": "Verification e-mail sent." }`
- **409** already verified.
- **429** rate limited. All must pass: 1 per 5 min per user, 5 per day per user, 10 per hour per IP (configurable in `config/verification.php`).

## Posts

Post object (`PostResource`):

```json
{
  "id": 1,
  "type": "lost",
  "status": "pending",
  "title": "Keys",
  "description": "Black keychain",
  "latitude": 56.95,
  "longitude": 24.1,
  "location_name": null,
  "event_date": "2026-11-12",
  "resolved_at": null,
  "images": [
    { "id": 1, "url": "http://localhost:8001/storage/posts/1/97a22f45-abc7-4a19-8e9c-e33255bd8de2.jpg" }
  ],
  "category": { "id": 1, "name": "Phones" },
  "user": { "id": 1, "username": "tester" },
  "created_at": "2026-11-12T19:25:35.000000Z",
  "updated_at": "2026-11-12T19:25:35.000000Z"
}
```

- `type`: `lost` | `found`
- `status`: `pending` | `approved` | `rejected` | `resolved`

### GET `/posts`

Public feed: **approved** posts only, newest first, 20 per page. Standard Laravel pagination (`?page=2`).

**200** `{ "data": [ Post, ... ], "links": {...}, "meta": {...} }`

### GET `/post/{post}`

Approved and resolved posts are public. Pending/rejected posts are visible only to the author and admins (send the token); everyone else gets `404`.

**200** `{ "data": Post }`

### POST `/posts`

Create a post. Requires a token **and a verified e-mail** (`403 "Your email address is not verified."` otherwise). Banned users get `403`. Saved with status `pending` until moderated.

Send as `multipart/form-data` when attaching photos.

| Field | Rules |
|---|---|
| `type` | required, `lost` or `found` |
| `category_id` | required, existing category id |
| `title` | required, max 100 |
| `description` | required, max 5000 |
| `latitude` | required, between -90 and 90 |
| `longitude` | required, between -180 and 180 |
| `location_name` | optional, max 150 |
| `event_date` | required, `Y-m-d`, today or earlier |
| `images[]` | optional, **max 5 files**; each jpg/jpeg/png/webp, max 5 MB |

Images:
- Stored at `storage/app/public/posts/<post id>/<uuid>.<ext>` and served from `/storage/posts/<post id>/<uuid>.<ext>`.
- The file name is a random UUID and the extension comes from the detected content type.
- Images are re-encoded server-side, so all EXIF data (including GPS) is stripped.
- Validation errors are reported per file, e.g. `images.0`, or on `images` for too many files.

Example:
```bash
curl -X POST http://localhost:8001/api/v1/posts \
  -H "Authorization: Bearer $TOKEN" -H "Accept: application/json" \
  -F type=lost -F category_id=1 -F title="Keys" -F description="Black keychain" \
  -F latitude=56.95 -F longitude=24.1 -F event_date=2026-11-12 \
  -F "images[]=@photo1.jpg" -F "images[]=@photo2.png"
```

**201** `{ "data": Post }`

### POST `/post/{post}`

Partial update: only the fields sent are validated and changed (same rules as create, all optional). Author only (`403` otherwise), not allowed on resolved posts. Any actual change sends the post back to `pending`.

Uses `POST` rather than `PUT`/`PATCH`. Images cannot be changed through this endpoint yet.

**200** `{ "data": Post }`

### DELETE `/post/{post}`

Author or admin. Also deletes the post's image files (`posts/<id>/`).

**204** no content.

## Not available yet

The database schema also covers messages, reports, notifications, account export/deletion and categories, but there are no endpoints for them yet. In particular there is no endpoint to list categories, so clients need valid `category_id` values from the database.
