# FindIT API (v1)

Base URL (local Docker): `http://localhost:8001/api/v1`

Interactive docs are also generated by Scramble (see `config/scramble.php`).

## Conventions

- Send `Accept: application/json` on every request, otherwise errors may come back as HTML redirects.
- JSON bodies use `Content-Type: application/json`. Endpoints that take files use `multipart/form-data`.
- **Auth:** Laravel Sanctum bearer tokens. Get one from `POST /login`, then send `Authorization: Bearer <access_token>`.
- Resource responses are wrapped in `{ "data": ... }`, except `POST /login`, which returns a plain object.
- Validation errors are `422` with the Laravel shape:
  ```json
  { "message": "The title field is required.", "errors": { "title": ["The title field is required."] } }
  ```
- Common errors: `401` missing/invalid token, `403` not allowed, `404` not found, `422` validation, `429` rate limited (check `Retry-After`).

## Auth

### GET `/captcha`

Hands out a CAPTCHA challenge for the registration form. The answer stays on the server, never in the response. Sent with `Cache-Control: no-store`.

The server's `CAPTCHA_TYPE` setting picks the kind, and `type` in the response says which one it is. Every response has `captcha_id`, `type` and `expires_in`, plus fields for that type:

**200**, `type: "hash"` (default): the browser finds the answer by itself
```json
{ "captcha_id": "9b1c6a52-...", "type": "hash", "algorithm": "SHA-256", "salt": "f3a9...", "challenge": "5e88...", "max_number": 3000000, "expires_in": 300 }
```
The answer is the whole number `n` between 0 and `max_number` for which `SHA-256(salt + n)` equals `challenge` (lowercase hex). The frontend solves it in a Web Worker.

**200**, `type: "math"`
```json
{ "captcha_id": "9b1c6a52-...", "type": "math", "question": "What is 7 + 5?", "expires_in": 300 }
```
Additions and subtractions of numbers from 1 to 20; the answer is never negative.

**200**, `type: "determinant"`
```json
{ "captcha_id": "9b1c6a52-...", "type": "determinant", "question": "What is the determinant of this matrix?", "matrix": [[3, 5], [2, 4]], "expires_in": 300 }
```
The answer is `a·d − b·c` and can be negative.

For every type:

- Send `captcha_id` and the answer as `captcha_answer` with `POST /register`.
- A challenge allows **one attempt**, right or wrong, and expires after `expires_in` seconds (`CAPTCHA_TTL_SECONDS`, default 300). Fetch a new one after any failed registration.

### POST `/register`

Creates an account. Sends a verification e-mail only while e-mail verification is turned on (`EMAIL_VERIFICATION_ENABLED`, off by default). Does **not** log the user in.

The CAPTCHA is checked first. Without a solved one the only error is on `captcha_answer`, so the other fields (e.g. "e-mail has already been taken") aren't validated until it passes.

| Field | Rules |
|---|---|
| `username` | required, 3–30 chars, `[a-zA-Z0-9_-]`, unique |
| `email` | required, valid e-mail, max 255, unique (stored lowercase) |
| `password` | required, min 8 chars |
| `password_confirmation` | must match `password` |
| `terms_accepted` | required, must be accepted (`true`/`1`) |
| `privacy_policy_version` | required, string |
| `captcha_id` | required, from `GET /captcha` |
| `captcha_answer` | required, whole number (`12` or `"12"`) |

CAPTCHA errors are `422` on `captcha_answer`: `"That answer is not correct. Try the new question."` or `"The question expired. Answer the new one."` (also used for a missing or unknown `captcha_id`).

**201**
```json
{ "data": { "id": 1, "username": "jane", "email": "jane@example.com", "email_verified_at": null } }
```

### POST `/login`

| Field | Rules |
|---|---|
| `email` | required, valid e-mail (case-insensitive) |
| `password` | required |
| `device_name` | optional, max 255 (token name, default `auth_token`) |

**200**
```json
{
  "access_token": "1|abc...",
  "token_type": "Bearer",
  "user": { "id": 1, "username": "jane", "email": "jane@example.com", "email_verified_at": null }
}
```
- `422` on wrong e-mail/password (error on `email`).
- `403` if the account is banned (only revealed after a correct password).
- Unverified accounts can log in; they just can't create posts.

### POST `/logout`

Revokes the current token. **200** `{ "message": "Successfully logged out." }`

### GET `/user`

The signed-in user. **200** `{ "data": { "id", "username", "email", "role", "email_verified_at", "must_verify_email" } }`.

Use `must_verify_email` to decide whether to ask the user to verify their address. It is always `false` while e-mail verification is turned off.
`401` if the token was revoked, so clients can use it to validate a stored token.

### GET `/user/posts`

The signed-in user's own posts in every status (`pending`, `approved`, `rejected`, `resolved`), newest first, 20 per page. Use it to find the posts whose suggested matches (`GET /post/{post}/matches`) the user can see.

**200** `{ "data": [ Post, ... ], "links": { ... }, "meta": { "current_page": 1, "last_page": 1, "total": 3, ... } }`

### GET `/user/export`

Downloads all of the signed-in user's personal data (GDPR data export) as one JSON file, sent with `Content-Disposition: attachment; filename="personal-data-<id>.json"`.

**200** a plain object (not wrapped in `data`) with `exported_at`, `account`, `posts` and `messages`. Uploaded files (avatar, post images, message attachments) are embedded as `{ "filename", "mime_type", "encoding": "base64", "content" }`, so the file is complete on its own. Other people in conversations are anonymised.

### DELETE `/user`

Suspends the signed-in account immediately, revokes all of its API tokens, and schedules permanent deletion after the 30-day grace period. The daily pruning task removes the account's posts, images and messages; report rows remain with a null reporter.

**202**
```json
{
  "message": "Your account is suspended and scheduled for permanent deletion.",
  "data": {
    "deleted_at": "2026-11-18T12:00:00.000000Z",
    "scheduled_deletion_at": "2026-12-18T12:00:00.000000Z"
  }
}
```

The account cannot sign in during the grace period. Personal data in backups may remain for up to 39 days after the request, based on the 7-day backup retention and daily cleanup schedule.

### GET `/email/verify/{id}/{hash}`

The link in the verification e-mail (signed URL, don't build it by hand).

- **200** `{ "message": "Email address verified." }`
- `403` invalid hash or signature, `410` already verified.

### POST `/email/resend`

Sends a new verification e-mail to the signed-in user.

- **202** `{ "message": "Verification e-mail sent." }`
- **409** already verified.
- **429** rate limited. All must pass: 1 per 5 min per user, 5 per day per user, 10 per hour per IP (configurable in `config/verification.php`).

## Categories

### GET `/category/query`

Every active item category, ordered by id. Retired categories are left out. Not paginated: the list is short and is meant for category pickers and filters.

**200** `{ "data": [ { "id": 1, "name": "Electronics" }, { "id": 2, "name": "Jewelry & Accessories" }, ... ] }`

## Posts

Post object (`PostResource`):

```json
{
  "id": 1,
  "type": "lost",
  "status": "pending",
  "title": "Keys",
  "description": "Black keychain",
  "latitude": 56.95,
  "longitude": 24.1,
  "location_name": null,
  "event_date": "2026-11-12",
  "resolved_at": null,
  "images": [
    { "id": 1, "url": "http://localhost:8001/storage/posts/1/97a22f45-abc7-4a19-8e9c-e33255bd8de2.jpg" }
  ],
  "category": { "id": 1, "name": "Phones" },
  "user": { "id": 1, "username": "tester" },
  "created_at": "2026-11-12T19:25:35.000000Z",
  "updated_at": "2026-11-12T19:25:35.000000Z"
}
```

- `type`: `lost` | `found`
- `status`: `pending` | `approved` | `rejected` | `resolved`
- `rejection_reason`: the moderator's reason (string or `null`). Only present on rejected posts (including posts taken down after publishing), and only for the author and admins. Cleared when the post is edited and goes back to moderation.

### GET `/posts`

Public feed: **approved** posts only, 20 per page. Newest **approval** first (`reviewed_at`, falling back to `created_at`), so a post that waited in the moderation queue appears at the top once it is approved. Standard Laravel pagination (`?page=2`).

**200** `{ "data": [ Post, ... ], "links": {...}, "meta": {...} }`

### GET `/posts/query`

Search the public feed by text, type, category and event-date range. Same posts and pagination as `GET /posts` (approved only, so resolved posts are left out), but ordered by `created_at`, newest first. All filters are optional and combine with AND.

| Query param | Rules |
|---|---|
| `q` | optional, max 100 chars |
| `type` | optional, `lost` \| `found` |
| `category_id` | optional, an id from `GET /category/query` |
| `date_from` | optional, inclusive `YYYY-MM-DD` lower bound for `event_date` |
| `date_to` | optional, inclusive `YYYY-MM-DD` upper bound for `event_date`; must be on or after `date_from` |

- Every word in `q` must appear in the title or the description (`red bus` won't match a post that only mentions "red").
- Case and diacritics are ignored: `atslegas` finds "Atslēgas" and the other way round.
- `%` and `_` are matched literally, not as wildcards.
- Without any filter it returns the same posts as `GET /posts`, though possibly in a different order.
- Pagination links keep the filters (`?q=keys&type=found&date_from=2026-01-01&page=2`).
- Text, type and category filters can be saved with `POST /saved-searches` to get notified about new matching posts. Date bounds apply only to the feed and are not stored in saved searches.

```bash
curl "http://localhost:8001/api/v1/posts/query?q=atslegas&type=found&category_id=2&date_from=2026-01-01&date_to=2026-06-30" -H "Accept: application/json"
```

**200** `{ "data": [ Post, ... ], "links": {...}, "meta": {...} }`

### GET `/post/{post}`

Approved and resolved posts are public. Pending/rejected posts are visible only to the author and admins (send the token); everyone else gets `404`.

**200** `{ "data": Post }`

### POST `/posts`

Create a post. Requires a token **and a verified e-mail** (`403 "Your email address is not verified."` otherwise). Banned users get `403`. Saved with status `pending` until moderated.

Send as `multipart/form-data` when attaching photos.

| Field | Rules |
|---|---|
| `type` | required, `lost` or `found` |
| `category_id` | required, existing category id |
| `title` | required, max 100 |
| `description` | required, max 5000 |
| `latitude` | required, between -90 and 90 |
| `longitude` | required, between -180 and 180 |
| `location_name` | optional, max 150 |
| `event_date` | required, `Y-m-d`, today or earlier |
| `images[]` | optional, **max 5 files**; each jpg/jpeg/png/webp, max 5 MB |

Images:
- Stored at `storage/app/public/posts/<post id>/<uuid>.<ext>` and served from `/storage/posts/<post id>/<uuid>.<ext>`.
- The file name is a random UUID and the extension comes from the detected content type.
- Images are re-encoded server-side, so all EXIF data (including GPS) is stripped.
- Validation errors are reported per file, e.g. `images.0`, or on `images` for too many files.

Example:
```bash
curl -X POST http://localhost:8001/api/v1/posts \
  -H "Authorization: Bearer $TOKEN" -H "Accept: application/json" \
  -F type=lost -F category_id=1 -F title="Keys" -F description="Black keychain" \
  -F latitude=56.95 -F longitude=24.1 -F event_date=2026-11-12 \
  -F "images[]=@photo1.jpg" -F "images[]=@photo2.png"
```

**201** `{ "data": Post }`

### POST `/post/{post}`

Partial update: only the fields sent are validated and changed (same rules as create, all optional). Author only (`403` otherwise), not allowed on resolved posts. Any actual change sends the post back to `pending`.

Uses `POST` rather than `PUT`/`PATCH`.

Photos can be changed too. Send as `multipart/form-data`:

| Field | Rules |
|---|---|
| `images[]` | new photos to add, same rules as when creating (jpg/png/webp, max 5 MB each) |
| `remove_images[]` | ids of this post's existing photos to delete. An id that isn't one of this post's photos is `422`. |

A post keeps at most 5 photos after the change (`422` otherwise). Adding or removing a photo counts as a change and sends the post back to `pending`.

**200** `{ "data": Post }`

### GET `/post/{post}/matches`

Suggested matches: posts that might be the other half of this one. Author or admin only (`403` otherwise).

A match is an approved post of the opposite type (lost ↔ found) in the same category, with an event date at most 7 days either side, less than 2 km away and not by the same user. Closest first, at most 20. Each post has an extra field `distance_m`, the distance in metres.

**200** `{ "data": [ Post, ... ] }`

### POST `/post/{post}/resolve`

Marks the post as resolved (the item was returned) and records `resolved_at`. Author only, and only for approved posts (`403` otherwise). Resolved posts stay public but can't be edited. They are deleted automatically six months after `resolved_at`.

**200** `{ "data": Post }`

### DELETE `/post/{post}`

Author or admin. Also deletes the post's image files (`posts/<id>/`).

**204** no content.

## Messages

Private messages between a visitor and the author of a post. Every message is tied to a post, the body is encrypted at rest, and responses never contain either party's e-mail address.

Message object:

```json
{
  "id": 1,
  "post_id": 1,
  "body": "I found your keys",
  "sender": { "id": 2, "username": "visitor" },
  "receiver": { "id": 1, "username": "tester" },
  "attachments": [
    { "id": 4, "type": "image", "mime_type": "image/jpeg", "size": 183422, "url": "https://…/api/v1/message-attachments/4?expires=…&signature=…" }
  ],
  "read_at": null,
  "created_at": "2026-11-12T19:40:00.000000Z"
}
```

Who talks to whom:
- A **visitor** always writes to the post's author, no `user_id` needed.
- The **author** must pass `user_id` (the visitor) to choose which conversation to send to or read. They can only answer someone who has already messaged them about this post.
- Only approved and resolved posts can be messaged. Pending and rejected posts return `404` to everyone except their author.

### GET `/messages/conversations`

Every conversation the signed-in user is in, one entry per post and other person, most recent first. Conversations about posts the user can no longer see are left out.

**200**
```json
{
  "data": [
    {
      "post_id": 15,
      "post_title": "Lost keys",
      "other_user": { "id": 7, "username": "Alex" },
      "last_message": { "id": 101, "body": "Hello, I found something similar.", "created_at": "2026-11-18T10:15:00.000000Z", "sender_id": 7 },
      "unread_count": 2
    }
  ]
}
```

`last_message.body` is `null` when that message only has photos or videos. `unread_count` counts messages from the other person that aren't read yet. To open one, use `GET /post/{post_id}/messages` (the author adds `user_id` = `other_user.id`).

### GET `/post/{post}/messages`

The conversation between the signed-in user and the other party about this post, oldest first, 50 per page. Received messages are marked as read (`read_at`).

| Query | Notes |
|---|---|
| `user_id` | Author only: the visitor whose conversation to read. `404` if that user hasn't written about this post. |

A user who is not part of any conversation on the post just gets an empty list.

**200** `{ "data": [ Message, ... ], "links": {...}, "meta": {...} }`

### POST `/post/{post}/messages`

Requires a token and a verified e-mail (`403` otherwise). Banned users get `403`.

| Field | Rules |
|---|---|
| `body` | string, max 2000. Required when there are no `attachments`. |
| `attachments[]` | optional, up to 3 photos or videos. Send as `multipart/form-data`. |
| `user_id` | author only, required: the visitor being answered. `422` if missing, `403` if that user hasn't messaged you about this post. |

Attachments:
- Photos: jpg, png, webp, max 5 MB. Videos: mp4, webm, mov, max 20 MB. Anything else is `422`.
- The type is checked from the file's content, not its name or header.
- Photos are re-encoded, which removes EXIF/GPS data. Videos are stored as sent.
- Files are kept on the private disk under a random name. Each attachment's `url` is a signed link that expires after 15 minutes; fetch the message again for a new one.

**201** `{ "data": Message }`

### GET `/message-attachments/{attachment}`

The `url` from a message attachment. No token needed, but the signature is: without a valid one, or after it expires, the answer is `403`. Returns the file with its `Content-Type`. Supports range requests, so videos can seek.

## Reports

### POST `/post/{post}/report`

Report a post to the moderators. Any signed-in user.

| Field | Rules |
|---|---|
| `reason` | required, 5–500 chars (trimmed first) |

**201**
```json
{ "data": { "id": 1, "post_id": 12, "reporter_id": 3, "reason": "Looks like spam", "status": "open", "created_at": "2026-11-14T10:00:00.000000Z" } }
```

- **409** `{ "message": "You have already reported this post." }`: one report per user per post.
- **404** if the post doesn't exist.
- `status`: `open` | `closed`. Admins see open reports in `GET /admin/moderation/queue` and close them with `POST /admin/reports/{report}/close`, which notifies the reporter (`report_reviewed`).

## Saved searches

A signed-in user can save the filters of `GET /posts/query` under a name. Every post that a moderator approves afterwards and that the search would find creates a notification for the search's owner.

Saved search object (`SavedSearchResource`):

```json
{
  "id": 1,
  "name": "My car keys",
  "q": "car keys",
  "type": "lost",
  "category": { "id": 2, "name": "Keys" },
  "created_at": "2026-11-14T10:00:00.000000Z",
  "updated_at": "2026-11-14T10:00:00.000000Z"
}
```

`q`, `type` and `category` are `null` when that filter isn't set ("any").

### GET `/saved-searches`

The user's own saved searches, newest first. Not paginated (at most 20).

**200** `{ "data": [ SavedSearch, ... ] }`

### POST `/saved-searches`

| Field | Rules |
|---|---|
| `name` | required, max 50 chars, unique among the user's saved searches |
| `q` | optional, max 100 chars |
| `type` | optional, `lost` \| `found` |
| `category_id` | optional, an id from `GET /category/query` |

At least one of `q`, `type` and `category_id` is required, otherwise every new post would match. Blank `q` counts as not set.

**201** `{ "data": SavedSearch }`

- **422** `{ "message": "You can save at most 20 searches. Delete one first." }`

### PATCH `/saved-search/{savedSearch}`

Renames the search. Only `name` can change (same rules as above), other fields are ignored. To change the filters, save a new search and delete the old one.

**200** `{ "data": SavedSearch }`

### DELETE `/saved-search/{savedSearch}`

Deletes the search and stops its notifications. Notifications it already created are kept.

**204** no body

Rename and delete return **404** for another user's search, so ids don't reveal that a search exists.

### Notifications

In-app notifications, stored in the `notifications` table (Laravel database channel). No e-mail is sent for them. The API's `type` is the notification class name in snake case, without `Notification`:

| `type` | Sent when | `details` |
|---|---|---|
| `saved_search_match` | An approved post matches one of the user's saved searches | see below |
| `possible_match` | An approved post is a suggested match for one of the user's posts | `{ "post_id", "post_title", "matched_post_id", "matched_post_title", "matched_post_type", "distance_m", "message" }` |
| `new_message` | Someone sends the user a message | `{ "message_id", "post_id", "post_title", "message" }` |
| `post_moderated` | An admin approves, rejects or takes down the user's post | `{ "post_id", "post_title", "status", "message", "reason" }` |
| `report_reviewed` | An admin closes a report the user made | `{ "report_id", "post_id", "post_title", "outcome", "message" }`, `outcome` is `action_taken` or `dismissed` |

`possible_match` uses the same rules as `GET /post/{post}/matches`. When a post is approved, its author and the authors of each matching post are notified, once per pair of posts.

Read notifications are deleted automatically 90 days after `read_at`. Unread ones are kept.

**Saved-search matches** are created when an admin approves a post (`POST /admin/posts/{post}/approve`) that matches a saved search. `details`:

```json
{
  "saved_search_id": 1,
  "saved_search_name": "My car keys",
  "post_id": 12,
  "post_title": "Found car keys",
  "post_type": "found",
  "message": "A new post matches your saved search \"My car keys\"."
}
```

- Matching uses exactly the same rules as `GET /posts/query`, so a notified post is always in the search's results.
- One notification per saved search and post. A post that is edited and approved again doesn't notify the same search twice. It does notify searches it didn't match before the edit.
- No notifications for the user's own posts, or to banned users.
- If several of a user's searches match the same post, each one notifies.

Notification object (`NotificationResource`):

```json
{
  "id": "1cf2b27d-e9ca-4468-8b90-127a6e45b411",
  "type": "saved_search_match",
  "details": { "post_id": 12, "post_title": "Found car keys", "...": "..." },
  "read_at": null,
  "created_at": "2026-11-14T10:00:00.000000Z"
}
```

The payload is called `details`, not `data`, so single notifications are still wrapped in `{ "data": ... }`.

#### GET `/notifications`

The user's notifications, newest first, 20 per page. `meta.unread_count` counts every unread notification, not just this page's.

**200** `{ "data": [ Notification, ... ], "links": { ... }, "meta": { "current_page": 1, "unread_count": 2, ... } }`

#### POST `/notification/{notification}/read`

Marks one notification as read. Marking it again keeps the first `read_at`. **404** for another user's notification.

**200** `{ "data": Notification }`

#### POST `/notifications/read`

Marks all of the user's notifications as read.

**204** no body

## Admin

All admin endpoints need the token of an account with role `admin`. Anyone else gets **403** `{ "message": "Forbidden. Administrator access required." }`.

### GET `/admin/users`

All accounts for moderation, ordered by username, 20 per page.

| Query parameter | Rules |
|---|---|
| `search` | optional, max 100 chars. Case-insensitive match anywhere in the username or e-mail |
| `status` | optional, `all` (default) \| `active` \| `banned` |

**200** `{ "data": [ AdminUser, ... ], "links": {...}, "meta": {...} }`

```json
{ "id": 7, "username": "anna", "email": "anna@example.com", "role": "user", "banned_at": null, "email_verified_at": null, "posts_count": 3, "created_at": "2026-11-14T10:00:00.000000Z" }
```

### POST `/admin/users/{user}/ban`

Bans a user and revokes all their tokens, so they are logged out straight away.

**200**
```json
{ "message": "User has been banned.", "data": { "id": 7, "username": "spammer", "banned_at": "2026-11-14T10:00:00.000000Z" } }
```

- Banning an already banned user keeps the original `banned_at` (and revokes tokens again).
- **422** `{ "message": "Administrator accounts cannot be banned." }`
- What a ban does: the user can't log in (`403`), create posts or send messages, and their posts disappear from the feed and return `404` to everyone except admins.

### POST `/admin/users/{user}/unban`

Lifts the ban. Their posts become visible again. Unbanning a user who isn't banned does nothing.

**200**
```json
{ "message": "User has been unbanned.", "data": { "id": 7, "username": "spammer", "banned_at": null } }
```

### GET `/admin/statistics`

Aggregate figures for a date range. The response contains no user or post-level personal data, so it can be shared outside the moderation team.

| Query parameter | Rules |
|---|---|
| `from` | optional date in `YYYY-MM-DD`; defaults to the first day of this month |
| `to` | optional date in `YYYY-MM-DD`; defaults to today and must be on or after `from` |

**200**
```json
{
  "data": {
    "from": "2026-11-01",
    "to": "2026-11-16",
    "posts_by_type_and_status": {
      "lost": { "pending": 3, "approved": 4, "rejected": 1, "resolved": 2 },
      "found": { "pending": 1, "approved": 2, "rejected": 0, "resolved": 5 }
    },
    "total_posts": 18,
    "by_type": { "lost": 10, "found": 8 },
    "by_status": { "pending": 4, "approved": 6, "rejected": 1, "resolved": 7 },
    "resolved_count": 7,
    "average_days_to_resolution": 3.42,
    "open_reports": 2,
    "banned_users": 1
  }
}
```

- `posts_by_type_and_status`, `total_posts`, `by_type` and `by_status` count posts **created** in the range. Every type/status pair is present, with `0` when unused.
- `resolved_count` and `average_days_to_resolution` cover posts **resolved** in the range. The average is `null` when there are none.
- `open_reports` and `banned_users` are current totals, not limited to the range.

### GET `/admin/moderation/queue`

Everything waiting for an admin: pending posts and open reports, oldest first. Not paginated.

**200**
```json
{
  "data": {
    "pending_posts": [ Post, ... ],
    "open_reports": [
      { "id": 3, "reason": "Spam", "status": "open", "created_at": "...", "reporter": { "id": 7, "username": "anna" }, "post": Post }
    ]
  }
}
```

`reporter` is `null` when the reporting account has been deleted, and `post` is `null` when the post is gone.

### POST `/admin/posts/{post}/approve`

Publishes a pending post. Notifies its author (`post_moderated`), the owners of saved searches it matches (`saved_search_match`) and the authors of suggested matches (`possible_match`).

**200** `{ "message": "Post approved.", "data": Post, "moderation": { "reviewed_by": 1, "reviewed_at": "..." } }`

**422** `{ "message": "Only pending posts can be approved." }`

### POST `/admin/posts/{post}/reject`

Rejects a pending post and notifies its author.

| Field | Rules |
|---|---|
| `reason` | optional, max 500 chars. Shown to the author |

**200** `{ "message": "Post rejected.", "data": Post, "moderation": { "reviewed_by": 1, "reviewed_at": "..." } }`

**422** `{ "message": "Only pending posts can be rejected." }`

### POST `/admin/posts/{post}/takedown`

Removes an already published (approved or resolved) post from the feed, for example after a report. The post gets status `rejected`, so only its author and admins can still see it, and the author is notified (`post_moderated`). The author can edit it, which sends it back to moderation.

| Field | Rules |
|---|---|
| `reason` | optional, max 500 chars. Shown to the author as `rejection_reason` |

**200** `{ "message": "Post taken down.", "data": Post, "moderation": { "reviewed_by": 1, "reviewed_at": "..." } }`

**422** `{ "message": "Only published posts can be taken down." }`

### POST `/admin/reports/{report}/close`

Marks a report as handled, records the admin in `reviewed_by` and removes it from the moderation queue. What happens to the post is a separate call (takedown, or banning the author). The reporter gets a `report_reviewed` notification; the post's author is not told about the report.

| Field | Rules |
|---|---|
| `outcome` | optional, `action_taken` \| `dismissed`. Without it, `action_taken` if the post is now rejected, otherwise `dismissed` |

**200** `{ "message": "Report closed.", "data": Report }` (same shape as `POST /post/{post}/report` returns)

**422** `{ "message": "This report is already closed." }`

### Categories (admin)

Responses are wrapped in `{ "data": ... }`. A category is `{ "id", "name", "retired_at", "posts_count" }`. `posts_count` tells which categories can be deleted (`0`) and which must be retired instead.

| Endpoint | Does | Response |
|---|---|---|
| `GET /admin/categories` | All categories, including retired ones, ordered by name. Not paginated | **200** `{ "data": [ Category, ... ] }` |
| `POST /admin/categories` | Adds a category | **201** `{ "data": Category }` |
| `PATCH /admin/categories/{category}` | Renames a category | **200** `{ "data": Category }` |
| `POST /admin/categories/{category}/retire` | Retires it: it can't be chosen for new posts, existing posts keep it, and `GET /category/query` leaves it out | **200** `{ "data": Category }` |
| `POST /admin/categories/{category}/restore` | Undoes a retirement | **200** `{ "data": Category }` |
| `DELETE /admin/categories/{category}` | Deletes an unused category | **204**, or **409** if a post uses it (retire it instead) |

`POST` and `PATCH` take `name`: required, max 50 chars, unique ignoring case (`422` otherwise).
